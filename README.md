*** 初版程式碼透過 Google AI Studio Gemini 3 生成 ***

**Web App 前端與使用者介面 (UI/UX)**
 - HTML5 & CSS3
 - Responsive Design (響應式設計) 確保手機、平板與電腦上體驗一致。
 - 使用 Leaflet 底圖，匯入建築物邊界、車格、柱號 GIS 資訊。
 - 使用 SVG 套圖呈現文字、外觀及圖例。若須修改文字，直接於 Illustrator 修改後重新匯出即可。
 - 使用按鈕輸入，減少手機原生鍵盤輸入占用畫面的次數。

**Web App 功能摘要**
 - 導航演算法 (Pathfinding) 採用 Dijkstra 演算法，計算最短路徑。
 - 定義車道 GIS 資訊，於車格中點與道路投影距離後渲染路徑。
 - 靜態網站，僅在瀏覽器運作，不依賴外部資料庫，使用PWA，確保在地下停車場無訊號時，仍能運作。
 - 具羅盤功能，點擊右上角羅盤按鈕使用裝置陀螺儀資訊，在沒有 GPS 情況下進行定向。
 - 可於按鈕搜尋車格後，設為終點，再到畫面上選取目前所在的位置，使用彈出視窗設定為起點。
 - 樓層切換：B2 觀眾停車場為主、B1 演職人員停車場為輔；右下角樓層鍵或輸入框左側的樓層鍵皆可切換。
 - 跨樓層導航：起訖點位於不同樓層時，先指引至「入口大廳風除室及梯廳」或「潮台菜旁通往1F榕樹廣場、戶外劇場樓梯」（自動取總距離最短者），再接續另一層的路線。
 - 「停泊即時資訊」尋車結果可按「指引」，直接將該車格設為終點並開始導引。
 - 網址加上 `?guide=<目的地>` 可直接帶入終點：車格代碼（例如 `B1F-052`）、柱號（例如 `A01`）或區域名稱（例如 `歌劇院B2票口`）；兩層皆有的柱號或區域預設取 B2，可加 `&floor=B1` 指定。可與 `?start=` 合用，開啟即顯示完整路線。
 - 定點 QR code 固定起點：網址加上 `?start=<起點名稱>`（例如 `?start=戲劇院B2票口`），開啟後該處即為起點，使用者在地圖上點選任一車格或柱號就直接設為終點並規劃路線；重新搜尋時起點保留，手動「設為起點」則取消固定起點。
   - 可用起點：geojson 中具 `road_id` 的區域名稱（如 戲劇院B2票口、歌劇院B2票口、音樂廳東側B2票口、音樂廳西側B2梯廳、營運辦公室、東側演職人員出入口…）或車格代碼（如 `B1F-052`）。
   - 兩層同名的區域預設取 B2，可加 `&floor=B1` 指定，例如 `?start=入口大廳風除室及梯廳&floor=B1`。
   - 製作 QR code 時建議將中文做 URL 編碼，例如 `?start=%E6%88%B2%E5%8A%87%E9%99%A2B2%E7%A5%A8%E5%8F%A3`。

**B1 圖資更新**
 - B1 圖資由 `tools/build_b1.py` 從 Excel（WKT）與 Illustrator 匯出的原始 SVG 產生 `parking-b1.geojson` 及 `B1-20260501-geo.svg`。
 - 轉換時以 SVG 建築物外框對應 WKT「結構牆1~26」擬合，再將建築物四個邊角對齊 B2 外牆角點；`--keep-wkt` 可改為沿用 Excel 內原本的 WKT 座標。
 - 指令：`python tools/build_b1.py <B1停車格.xlsx> <B1原始.svg>`（需 openpyxl、numpy）

**解決問題**
 - 既有系統未提供柱號，亦無格號搜尋，所有檢索需先有車牌號碼，才能進行檢索。</br>
 --> 本系統無須輸入車牌號碼，即可對已知資訊進行搜尋定位。
 - 牆體及建築物結構過度強調，但間接遮蔽了方向性，產生隧道效應。</br>
 --> 僅對使用者肉眼可見的牆面進行標示，並著重於車道與牆體的關係，及車格號、柱號的相互位置對照。
 - 既有系統僅提供路徑，但無法對路徑進行拖拉、放大，或旁鄰車格或路徑上車格號碼交互檢視。</br>
 --> 可提供縮放，所有車格號碼可互相對應。雖方向恆向北邊，但可以啟動羅盤檢視現在行進間路徑是否方向一致。
